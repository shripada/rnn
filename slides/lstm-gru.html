Recurrent Neural Networks · Part 2

Memory with a door

How LSTMs and GRUs hold on to a memory for hundreds of steps.

France→ … forty words later …→ French
Welcome back. Last time ended on a problem: plain RNNs forget the far past. Today: two cells designed to fix that, the LSTM and the GRU. The strip is the kind of link we want: a clue from forty words ago deciding the next word.

Last time

Plain RNNs forget the far past

  1. An RNN reads one step at a time and keeps a running memory.
  2. It uses the same weights at every step.
  3. It learns by passing blame backwards through time, and that blame fades over long distances.
Blame, × 0.5 each step back

After 10 steps: about 0.001 of the blame is left. After 20: about one millionth.

Today: two cells built to fix this. The LSTM (1997) and the GRU (2014).

Quick recap, ask the room for the three sentences before revealing. The key one is the third: blame fades as it travels back. We fixed exploding blame with clipping. Fading blame needs a new design, which is today.

Why it matters

Some clues are a long way back

I grew up in France. My parents moved to London when I was twelve, and I went to school there, played football every weekend and worked in a café for years, so these days I'm most comfortable in English, but I still speak fluent ______.

  • The word that decides the blank is about 40 words back.
  • To learn that link, the blame for a wrong guess at the blank has to reach France.
  • In a plain RNN it arrives as almost nothing, so the network never learns to remember it.
Ask: what's the blank? Everyone says French, because they kept "France" in mind across a long, distracting passage. That's a long-range dependency. Programming languages have the same thing: a bracket opened 50 lines earlier.

The root cause

Every step rewrites the whole memory

  • At every step, the plain RNN mixes the old memory with the new input and squashes the result.
  • That happens even when the input is just a space.
  • Blame travelling back goes through the same mixing and squashing at every step, so it shrinks every step too.
The fade is built in: same weights, same squash, every step, with no way to say "nothing happened, leave the memory alone". That missing ability is exactly what the LSTM adds.

A little history

The LSTM: Hochreiter and Schmidhuber, 1997

1991Sepp Hochreiter's thesis (Munich) shows why blame fades in plain RNNs: the problem from Part 1.
1997Hochreiter and Jürgen Schmidhuber publish the fix: Long Short-Term Memory.
2000Felix Gers, Schmidhuber and Fred Cummins add the forget gate.
2010sLSTMs power speech recognition and machine translation, including Google Translate.
The same person who diagnosed the fading-blame problem designed the fix six years later. The name: a short-term memory (the hidden state) that can last a long time.

The LSTM's idea

Add a second memory that is left alone

  • A new memory, the cell state, runs straight through every step.
  • Each step can only do two things to it: erase some of it, or add something.

“The cell state is kind of like a conveyor belt.”

Christopher Olah, “Understanding LSTM Networks” (2015)

Long Short-Term Memory, Hochreiter and Schmidhuber, 1997. The belt is not mixed with weights or squashed at every step. If a step decides nothing needs to change, the memory goes through exactly as it was. The old hidden state still exists, as the cell's output: we'll see that next.

Try it · gates

Gates: learned dials from 0 to 1

A gate multiplies a signal by a number between 0 and 1.

signal in0.80
0.50
signal out

Each gate is a tiny network that looks at the current letter and the memory, and sets its own dial. The dial settings are learned from data, like every other weight.

Drag to 0: nothing gets through. Drag to 1: everything gets through. The important part is that the network learns when to open and close each gate, based on what it is reading. Olah: "A value of zero means let nothing through, while a value of one means let everything through."

The LSTM cell

Three gates around the belt

Forget gate ft (keep?): how much of the old belt to keep. 1 = keep it all, 0 = wipe it.

Input gate it (write?): how much of the candidate to add to the belt.

Candidate c̃t (new info): what could be written. Not a gate.

Output gate ot (show?): how much of the belt to show as the output right now.

Walk the picture left to right. The belt only ever meets a multiply (keep) and an add (write). The output is a filtered view of the belt, so the cell can know something without saying it yet. The original 1997 LSTM had no forget gate; Gers and colleagues added it in 2000 so the cell could reset itself. The next two slides open the boxes: what a gate is made of, then the full step as equations.

The LSTM cell · inside a gate

Every gate is a tiny network

old output ht−1+ letter xt→ its own weights + bias→ squash→ one dial per memory slot
  • All four boxes in the cell read the same two things: the cell's last output and the current letter.
  • Each box has its own weights, so each learns to react to different things. The input gate might learn to open on a capital letter; the forget gate might learn to close at a full stop.
  • The memory is a list of numbers (256 in our demo), and a gate sets one dial per number. It can keep one slot and wipe the slot next to it.
  • Gates squash with the sigmoid, which outputs 0 to 1, like a dial. The candidate uses tanh, which outputs −1 to 1, because new information has to be able to push a slot down as well as up.
The two squashes
A gate is the same shape as a plain RNN layer: weights times (old output, input), plus a bias, then a squash. The only difference is the squash. Sigmoid lands between 0 and 1, which is exactly what a dial needs: 0 lets nothing through, 1 lets everything through. The new-info box is content, not a dial, so it uses tanh and can be negative. Interview question to expect: "why sigmoid for gates and tanh for the candidate?" Gates work slot by slot: the forget gate is a whole list of dials, one for each number on the belt.

The LSTM cell · one full step

One LSTM step, in four moves

1
Keep? The forget gate decides how much of each belt slot to keep.
ft = σ(Wf·[ht−1, xt] + bf)
2
Write? Make a candidate (the new information), and let the input gate decide how much of it to write.
it = σ(Wi·[ht−1, xt] + bi)
c̃t = tanh(Wc·[ht−1, xt] + bc)
3
Update the belt. Erase, then add.
ct = ft ⊙ ct−1 + it ⊙ c̃t
4
Show? The output gate picks how much of the belt to show as this step's output.
ot = σ(Wo·[ht−1, xt] + bo)
ht = ot ⊙ tanh(ct)

[h, x] means the two lists joined into one. σ is the sigmoid (0 to 1). ⊙ means multiply slot by slot. There are four weight matrices instead of one, which is why the LSTM is about 4× the size of a plain RNN.

This is the slide to be able to write on a whiteboard. Read it as a story: keep, write, update, show. Point at move 3: the belt only meets a slot-by-slot multiply and an add. No weight matrix and no squash, which is why blame survives along it (right after the worked example). The output h_t goes two places: to the prediction, and back into all four boxes at the next step. Notation follows Dive into Deep Learning (D2L) §10.1 and Olah.

Try it · be the gates

You are the gates

A one-number LSTM over 8 steps. Click a gate to cycle it 0 → ½ → 1. Something worth remembering arrives at step 1, and a distraction at step 4.

○Hold it. Keep the belt at exactly 1 all the way to step 8.
○Forget on cue. Hold it through step 5, then wipe it to 0 from step 6.
○Keep a secret. Show 0 for steps 1–7, then show 1 at step 8.
Simplified so the arithmetic is visible: belt = keep × old belt + write × input, output = show × belt. In a real LSTM the gates set themselves from the input; here the audience plays that role. Hold it: write at step 1, keep = 1 after that, and don't write at step 4. Forget: keep = 0 at step 6. Secret: show = 0 until step 8. A plain RNN can't do any of these: its memory fades whatever you do.

Following “France” through the gates

A plain RNN would have to carry “France” through 40 rounds of mix-and-squash. The LSTM only needs one dial to stay at 1.

This is "you are the gates" applied to the real sentence. Stress that it's idealised: real dials are fuzzy (0.97, not 1), and the job is spread across many slots. Training finds these settings because the blame for a wrong guess at the blank can now travel back to "France" along the belt while keep stays near 1. That's the next slide. Ask: which dial would you get wrong if you let the "English" phrase in? (write.) What if the cell had no show gate? (It would have to push "France" into every output for 40 words. That's exactly the GRU's situation.)

Why it works

On the belt, blame is only multiplied by the forget gate

Going back one step along the belt, the blame is multiplied by the forget gate. No weights, no squashing. At 1 (keep everything), the blame passes back untouched.

0.980

A plain RNN can't hold its multiplier at 1: the same weights and squashing apply every step. A gate can sit at 1 whenever the network wants to remember.

The maths is the same "multiply by the same number again and again". The difference is which numbers are reachable. For the plain RNN the multiplier is set by its weights and the squash, and in practice it's well below 1 (0.6 here). For the LSTM it's a gate value, and "keep everything" is a normal thing for a gate to output. Drag it to 0.5 to show that a closed gate forgets on purpose.

A little history

The GRU: Cho and colleagues, 2014

2014Kyunghyun Cho and colleagues in Yoshua Bengio's lab (Montréal) propose it while building a machine translation system.
GoalKeep the LSTM's trick of a memory that is changed by adding, with fewer gates and fewer weights.
Seventeen years after the LSTM. Same idea, simplified: the next slide shows what was dropped.

A lighter design

The GRU: one memory, two gates

One memory, ht. It is also the output, so there is no belt and no output gate.

Update gate zt: how much of the old memory to keep. The rest, 1 − zt, comes from the candidate.

Reset gate rt: how much of the old memory the candidate gets to see.

Candidate h̃t: the fresh draft. Not a gate.

Gated Recurrent Unit, Cho et al., 2014. Walk the picture: the top line is the only memory. The update gate's × on it plays the LSTM's keep gate, and 1 − z plays the write gate, so keep 70% means write 30%. Reset only affects the candidate: it filters the old memory before the candidate looks at it. Convention warning for anyone reading further: some sources, including Olah's diagram, flip which end of the dial means "keep".

The GRU · one full step

One GRU step, in three moves

1
Reset? Decide how much of the old memory the candidate is allowed to look at.
rt = σ(Wr·[ht−1, xt] + br)
2
Candidate. Draft a new memory from the letter and the part of the old memory that reset lets through.
h̃t = tanh(Wh·[rt ⊙ ht−1, xt] + bh)
3
Update. Keep a share z of the old memory and fill the rest from the candidate.
zt = σ(Wz·[ht−1, xt] + bz)
ht = zt ⊙ ht−1 + (1 − zt) ⊙ h̃t
When does reset matter?

Reset near 0 builds the candidate from the current letter alone, a clean start. That's useful when a new sentence or a new name begins and the old context would only get in the way.

Compared with the LSTM

z does the job of the LSTM's forget gate (keep) and 1 − z the job of its input gate (write). ht is both the memory and the output. Three weight matrices make it about 3× a plain RNN.

Same whiteboard drill as the LSTM: reset, draft, update. The z_t ⊙ h_{t−1} term in move 3 is the GRU's belt: a slot-by-slot multiply and an add, no weights, no squash. Its blame multiplier is z, which can sit near 1. People often confuse the two gates. Update decides how much old memory to keep. Reset only decides what the draft gets to see. Notation is D2L's (z = 1 keeps), the same as PyTorch.

The common question

Which one should I use?

They're about the same.

  • Careful comparisons found no clear winner (Chung et al., 2014; Greff et al., 2015). Both beat the plain RNN.
  • The GRU is smaller and faster.
  • The LSTM can hold information without showing it, which sometimes helps.
  • In practice: try both, and keep whichever does better on held-out text.
This is also a good interview answer: say they perform similarly, give the trade-off, and say you'd choose by validation score.

Recap

Three sentences to remember

  1. Gated cells add a memory that is changed only by erasing and adding, not rewritten at every step.
  2. Gates are learned dials from 0 to 1. The LSTM has forget, input and output gates (keep, write, show); the GRU has update and reset.
  3. When the forget gate sits near 1, blame flows back across many steps, so the network can learn from the far past.
Ask a student to explain each sentence back, then ask the France question again: why can an LSTM learn it when a plain RNN can't?
