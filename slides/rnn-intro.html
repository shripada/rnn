Where we are

You already know two things

A neural network

Numbers go in, pass through layers of weights, and numbers come out.

It learns by repeating three steps: guess, check how wrong it was, adjust the weights a little.

word2vec

Every word becomes a list of numbers, a vector.

Words used in similar ways get similar vectors.

king − man + woman ≈ queen

Today's question: what if the input is a whole sentence?

Quick recap of what they know. word2vec gives us a vector per word. But a sentence is a sequence of words. How do we feed that to a network?

Problem 1 · Order

Word order changes the meaning

A common shortcut: look up each word's word2vec vector and take the average.

dogbitesman
average
manbitesdog
average

Same three words, so the same average. The network can't tell who bit whom.

Ask the room: are these the same news story? No. But the average of the vectors is identical, because averaging ignores order. We need something that reads words in order.

Problem 2 · Length

Sentences come in every length

Hi.1 word
IgrewupinFrancesoIspeakfluent?10 words
  • A regular network has a fixed number of input slots.
  • Cut long sentences short? You lose words. Pad short ones? You waste slots.
  • And in the second sentence, the clue for ? is France, five words back.
Second problem: fixed input size. Also notice that the useful clue, France, is far from the blank. Whatever we build needs to remember things from several steps back.

The idea

Read one piece at a time, and keep notes

When you read a mystery novel, you don't reread the whole book on every page. You carry a running summary in your head: who's who, what happened, who looks guilty.

1 · One step at a time

Read one word (or letter) per step, in order.

2 · Update the memory

After each step, rewrite a small vector of notes: the hidden state.

3 · Same rule every step

The step is identical whether it's word 2 or word 200.

That's a recurrent neural network: the same step, recurring.

The hidden state is just a vector, like a word2vec vector, but it summarises everything read so far instead of one word.

Inside one step

Two things in, new memory out

In words:

new memory = squash( old memory mixed with this word )

"Mixed" means multiplied by weight matrices the network learns. "Squash" (tanh) keeps every number between −1 and 1.

ht = tanh(Whh·ht−1 + Wxh·xt + b)

Only show the formula as a label; the words version is what matters. It's a normal dense layer with one extra input: its own previous output. x could be a word2vec vector or a one-hot letter. The output y is computed from the new memory with one more weight matrix.

Unrolling

The same step, drawn once per word

Four boxes, but one network. Each box is the same step with the same weights. Only the memory changes.

Click through word by word. Emphasise: unrolling is just a way of drawing the loop over time. h4 has been influenced by all four words, in order.

Why this solves both problems

Same weights at every step

Order ✓

"dog bites man" and "man bites dog" are read in a different order, so they leave a different memory at the end.

Any length ✓

A longer sentence just means more steps. The number of weights never changes.

99,393

weights in today's demo model. The same 99,393 read a 4-letter prompt or a 1,000,000-letter play.

Parameter sharing. Also a bonus: a pattern learned at position 3 is recognised at position 300, because the same weights apply everywhere.

Try it · memory in one number

How long does a memory last?

The smallest possible RNN: memory is a single number. At step 1 it reads a "1", then only zeros. Anything left after step 1 is pure memory.

w = 0.60

Rule: h = tanh(w × old h + input). Drag w to 0: instant amnesia, it becomes a normal feed-forward net. Below 1: memory fades a bit at every step. Near or above 1: it holds on. Remember the fading: it comes back when we talk about training.

What RNNs are used for

Three shapes of task

Many → one

Read a whole review, give one answer.

"Loved it!" → positive

One → many

Start from one thing, produce a sequence.

a start letter → a whole paragraph

Many → many

An answer at every step.

predict the next letter after each letter

Same RNN, we just choose which inputs to feed and which outputs to read. Our demo uses all three: training is many-to-many, "predict" is many-to-one, "generate" is one-to-many where each output is fed back in as the next input.

Connecting to word2vec

word2vec for the words, an RNN for the sentence

word2vec knows what each word means. The RNN reads them in order and builds the meaning of the sentence.

Pipeline: each word is looked up in word2vec, giving x1..x4. The RNN reads them in order. We read only the final memory h4 and put a small classifier on top. That's many-to-one sentiment analysis.

Training

Learning: guess, check, adjust, through time

  • Same loop as any network: guess, check how wrong (the loss), adjust the weights.
  • The twist: a bad guess at step 5 might be caused by something read at step 1. So the blame has to travel backwards through the steps.
  • This is called backpropagation through time (BPTT). It's ordinary backpropagation on the unrolled picture.
No calculus needed: blame is passed backwards one step at a time. Point at the arrows: they get thinner further back. That's the next slide.

The catch

Blame fades as it travels back

Each step back, the blame gets multiplied by roughly the same number. If that number is 0.5:

steps back151020
× 0.5 each step0.50.030.0010.000001
× 2 each step2321,0241,048,576

Vanishing: the network barely learns from things far back, like France five words earlier.

Exploding: huge, wild updates. Fix: gradient clipping, which caps the size.

This is the same fading you saw on the slider, now happening to the learning signal. Clipping fixes exploding. Vanishing is harder and is why newer cells were invented. We'll name that at the end, not today.

Demo

An RNN that read Shakespeare

Task: read text one character at a time and predict the next character.

Data: about 1.1 million characters of Shakespeare's plays, 65 different characters.

Model: the plain RNN from today. 256 numbers of memory, 99,393 weights, trained for about 25 seconds on a laptop.

The text is split three ways

TRAIN80%the textbook it studies
VAL10%practice quizzes during training
TEST10%the final exam: scenes it has never seen
Characters, not words, so no word2vec here: each character is a one-hot vector. Same idea though. The split is by position, so TEST is literally different scenes.

Demo · training

2,000 rounds of guess, check, adjust

Each round: take 64 random 100-character snippets, guess the next character at every position, measure the loss, nudge the weights.

loss at the start

4.17

Pure guessing. Like choosing between all 65 characters equally.

loss after training

≈ 1.5

Like hesitating between only about 4 or 5 characters.

A handy reading of the loss: eloss ≈ how many characters the model is still choosing between. e4.17 = 65, e1.5 ≈ 4.5.

Loss is cross-entropy, but you don't need the formula: lower means more confident and right. The e-to-the-loss trick turns it into "number of choices".

Try it yourself

    
The demo is about 500 lines of Python

    
# train a fresh model (~25 s on a laptop)
uv run demo/char_rnn.py train
# grade it on the unseen TEST text
uv run demo/char_rnn.py test
# top guesses for the next character
uv run demo/char_rnn.py predict "KING RICHAR"
# let it write 300 new characters
uv run demo/char_rnn.py generate "ROMEO:" --n 300

    
Based on Andrej Karpathy's char-rnn and his essay "The Unreasonable Effectiveness of Recurrent Neural Networks".
