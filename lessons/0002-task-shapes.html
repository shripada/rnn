Write the hidden-state update equation.
h_t = tanh(W_hh·h_{t−1} + W_xh·x_t + b_h), with y_t = W_hy·h_t and h_0 = 0.
Why does the parameter count not depend on sequence length?
Parameter sharing: the same Wxh, Whh, Why are reused at every time step. A longer sequence just means more loop iterations.
Inputs have 10 features, hidden size is 32. Shape of Whh?
32 × 32. It maps hidden to hidden, so it is always square (n × n), whatever the input size.

One idea: choose which steps get inputs and which give outputs

In Lesson 1 every step had an input xt and could produce an output yt. Real tasks don't all look like that. Sometimes there's one input and many outputs; sometimes many inputs and a single answer. The RNN cell doesn't change. What changes is:

  1. at which steps you feed an input, and
  2. at which steps you read an output (and compute the loss).
“Notice that in every case are no pre-specified constraints on the lengths sequences because the recurrent transformation (green) is fixed and can be applied as many times as we like.”Karpathy, The Unreasonable Effectiveness of RNNs. The typo is in the original. The “fixed recurrent transformation” is Lesson 1's parameter sharing.

Three details interviewers probe

1 · Many-to-one: why the last hidden state?

For sentiment analysis you read the whole sentence and make one prediction. You attach the classifier to the final hidden state hT, because that is the only state that has seen every word: it's the running summary from Lesson 1, taken at the end. The outputs y1…yT−1 are simply never computed or never used.

2 · One-to-many: the output becomes the next input

To generate a sequence, the network samples an output at step t and feeds it back in as the input at step t+1 (the dashed arrows). Karpathy's character-level model generates text exactly this way: We sample from this distribution, and feed it right back in to get the next letter.1

3 · Synced vs encoder–decoder: are the sequences aligned?

Both take a sequence in and give a sequence out. The question to ask is: does output t correspond to input t?

  • Yes (tag each word, label each video frame): the lengths match and the positions line up, so use synced many-to-many.
  • No (translation): “I am hungry” → “J'ai faim” has a different length, and word order can differ. Output 1 may depend on input 3, which hasn't been read yet at step 1. So you have to read everything first.

That's the encoder–decoder (seq2seq) design. An encoder RNN reads the input and compresses it into a fixed-size context vector c, which is its final hidden state. A decoder RNN starts from c and generates the output one token at a time, feeding each output back in, until it emits a special <eos> (end-of-sequence) token.2 Sutskever, Vinyals & Le made this work at scale for translation in 2014 with two LSTMs: one maps the input “to a vector of a fixed dimensionality,” the other decodes from it.3

Look ahead: squeezing a whole paragraph into one fixed vector c is a squeeze. Bahdanau, Cho & Bengio called it out directly: the use of a fixed-length vector is a bottleneck.4 Their fix, letting the decoder look back at every encoder hidden state, is called attention. It's the bridge from RNNs to Transformers, and we'll return to it at the end of the course.

“The RNN cell is the same in every setting; the task decides which steps receive inputs and which outputs we use. Classification is many-to-one: I use the final hidden state. Tagging is synced many-to-many. Translation needs an encoder–decoder because input and output lengths and orders differ: the encoder compresses the source into a context vector and the decoder generates until an end-of-sequence token.”

Drill: name the shape

Eleven tasks, shuffled. Pick a shape for each and you'll get the diagram as feedback straight away. Any you miss come back at the end until you get them right. For each one, ask yourself: how many inputs, how many outputs, and do they line up?

Flag an email as spam or not spam, reading it word by word.
A whole sequence in, one label out. Classify from the final hidden state.
Tag every word in a sentence as a person, place, or other (named-entity recognition).
One label per word, aligned position by position.
Translate an English sentence into Hindi.
The output length and word order differ from the input, so read everything first, then generate until <eos>.
Write a caption sentence for a photo.
Karpathy's own example: one input (the image), then a sequence of words, each fed back in.
Predict tomorrow's temperature from the last 30 days of readings.
Thirty inputs, one number out. Read it from the final hidden state.
Generate a melody given only a genre label like “jazz”.
A single conditioning input, then free generation with outputs fed back as inputs.
Classify one 28×28 image of a handwritten digit.
A fixed-size input and a fixed-size output with no sequence anywhere. You don't need recurrence.
Mark every frame of a video as “goal scored” or “not”.
Karpathy's example (5): one label per frame, aligned.
Summarise a news article into two sentences.
Long input, short output, not aligned. Encode the article, then decode the summary.
During training of a character-level text model, predict the next character at every position.
A trap: generation is one-to-many, but training on known text is synced. Every input character has an aligned target (the next character), and each step's output gets a loss.
Answer a typed question with a full-sentence reply (a chatbot).
Question in, a reply of any length out, not position-aligned. This is the classic seq2seq framing.

Check yourself

1. In many-to-one sentiment classification, which hidden state feeds the classifier?
hT is the only state that has seen the whole sentence. (In practice people sometimes also pool all states, but the final hidden state is the canonical answer.)
2. Why is a synced many-to-many RNN a poor fit for English → French translation?
A synced model emits output t at step t, before it has read the rest of the sentence. Translation isn't aligned that way, which is why D2L calls the inputs and outputs “variable-length unaligned sequences.”2
3. In the original seq2seq model, what passes from the encoder to the decoder?
The encoder's final hidden state is the context vector. “One vector per word” is what attention later adds to fix the bottleneck.4
4. When a char-RNN generates text, where does the input for step t+1 come from?
At generation time there's no ground truth, so the model feeds its own sample back in. During training you feed the true characters, which is why training is synced (the drill's trap card).
5. How does a seq2seq decoder know when to stop generating?
The end-of-sequence token is part of the vocabulary. The decoder learns to predict it when the output is complete.2

Say it out loud

Name all five shapes with one example each.
One-to-one (image classification) · one-to-many (image captioning) · many-to-one (sentiment) · synced many-to-many (per-frame video labels / word tagging) · encoder–decoder (translation).
Sketch the encoder–decoder on paper. Where's the bottleneck?
Encoder cells read x1…xn, and the final hidden state becomes context c. Decoder cells start from c, take <bos> then each previous output as input, and emit y1… until <eos>. The bottleneck is c: the whole input has to fit into one fixed-size vector.
Generation is one-to-many, but training a char-RNN is synced. Why the difference?
In training you know the whole text, so at every step you feed the real character and compare the output to the real next character. That's aligned, with a loss at every step. At generation time there's no text to feed, so the model feeds its own samples back in.
