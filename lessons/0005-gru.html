GRU: The Lighter Gate

The LSTM's trick with fewer parts: one state, two gates.

By the end you can write the GRU's four equations, map each of its gates onto the LSTM's, explain why it also keeps gradients alive, and answer the classic follow-up: “LSTM or GRU: what's the difference, and which would you use?”

Warm-up: Lesson 4

Answer from memory, then reveal.

Name the LSTM's three gates and what each one controls.
Forget gate: how much of the old cell state to keep. Input gate: how much of the new candidate to write. Output gate: how much of tanh(ct) to show as ht.
Along the cell state, what is ∂ct/∂ct−1, and why does that help?
The forget gate ft. There's no weight matrix and no tanh in that path, so when the gate is near 1 the gradient passes back almost unchanged.
In the gate simulator, what settings held a value unchanged?
Forget = 1, input = 0. Notice those two always moved in opposite directions when you were holding or overwriting. The GRU builds that into the design.

The idea: tie “keep” and “write” together

When you played the LSTM's gates, holding meant f = 1, i = 0 and overwriting meant f = 0, i = 1. The Gated Recurrent Unit (GRU), from Cho et al. (2014),1 makes that a rule: one gate decides the mix, and whatever fraction is kept, the rest comes from the new candidate. Olah: It combines the forget and input gates into a single “update gate.” It also merges the cell state and hidden state, and makes some other changes.2

So a GRU has:

  • one state, ht, like a vanilla RNN (no separate ct);
  • an update gate zt: keep the old state or replace it with the candidate;
  • a reset gate rt: how much of the old state the candidate is allowed to look at;
  • no output gate: everything in the memory is always visible.

The GRU cell

rt = σ( Wr·[ht−1, xt] + br )    reset gate
zt = σ( Wz·[ht−1, xt] + bz )    update gate
h̃t = tanh( Wh·[rt ⊙ ht−1, xt] + bh )  candidate
ht = zt ⊙ ht−1 + (1 − zt) ⊙ h̃t

This is the convention of Dive into Deep Learning (D2L) §10.2 and of PyTorch: z = 1 keeps the old state.3 Watch out: Olah's diagram and some other sources swap z and 1 − z, so there z = 1 means “take the candidate”. Both are the same model; in an interview, say which convention you're using.

D2L on the two gates:3

  • Update gate: Whenever the update gate Zt is close to 1, we simply retain the old state. When it's close to 0, the new latent state Ht approaches the candidate latent state.
  • Reset gate: Whenever the entries in the reset gate Rt are close to 1, we recover a vanilla RNN candidate. Near 0, any pre-existing hidden state is thus reset to defaults: the candidate is built from the input alone.

Play: be the GRU's gates

Same setup as Lesson 4: a one-number GRU over 8 steps, and you set the gates. Here the candidate is h̃ = tanh(x + r · hprev), so the reset gate decides whether the old memory leaks into the new proposal.

○Store and hold. Write x1 and keep h between 0.9 and 1 at every step, ignoring the −1 at step 5.
○Clean overwrite. Hold h ≥ 0.9 through step 4, then make h5 exactly tanh(x5) ≈ −0.76, with no trace of the old memory. (You'll need both gates.)
○Fade slowly. Store x1, then make h shrink at steps 2, 3 and 4, each step between 40% and 60% of the one before. (A vanilla RNN fades like this whether you want it to or not; here it's a choice.)

Now try Lesson 4's Silent memory challenge here: store x1, keep h at 0 until step 8, then show it. You can't. With no output gate and no separate cell state, the only way to store something is to have it in h, where everything downstream sees it. That's the main thing the GRU gives up for its simplicity.

Gradients: the same highway

Look at the last equation: ht = zt ⊙ ht−1 + …. The zt ⊙ ht−1 term is a direct path from the old state to the new one, with no weight matrix and no tanh. Along it:

∂ht / ∂ht−1 = zt   (along the direct path)

That's the LSTM's argument again, with the update gate playing the forget gate's role. When z ≈ 1 (keep), the gradient passes back almost unchanged. (Gradient also flows through the candidate and the gates; those paths still vanish, as in the LSTM.)

○Same highway. With T = 100, keep the GRU's signal at step 1 above 0.1 while the RNN's is below 10−6.

Which is better? Neither, reliably. Chung et al. compared them directly and found the GRU comparable to LSTM, with both clearly beating the vanilla RNN.4 Olah summarises a larger study:5 Greff, et al. (2015) do a nice comparison of popular variants, finding that they're all about the same.2 D2L: Compared with LSTMs, GRUs achieve similar performance but tend to be lighter computationally.3

A sensible interview answer: start with whichever your framework or team defaults to; try a GRU when you need a smaller or faster model; try an LSTM when the task may need to hold information without exposing it, or for very long dependencies; and pick by validation score, not by theory.

“A GRU is a simplified LSTM. It merges the cell and hidden state into one vector and uses two gates. The update gate z blends the old state with a new candidate: ht = z ⊙ ht−1 + (1 − z) ⊙ h̃t, so it plays the role of the LSTM's forget and input gates tied together. The reset gate controls how much of the old state goes into the candidate. There's no output gate. That direct z ⊙ ht−1 term gives the same gradient highway as the LSTM's cell state. It has about three quarters of the LSTM's parameters, and in practice the two perform similarly, so the choice is usually empirical.”

Check yourself

1. Which pair of LSTM gates does the GRU's update gate replace?
z plays the forget gate (keep this much old state) and 1 − z plays the input gate (write this much candidate). The output gate has no GRU counterpart.
2. Using ht = z ⊙ ht−1 + (1 − z) ⊙ h̃t, what does z = 1 do?
z = 1 gives ht = ht−1. In Olah's convention the formula is flipped, so always state which one you mean.
3. What does the reset gate rt control?
r multiplies ht−1 inside the candidate's tanh. r ≈ 0 means the candidate is computed from xt alone. Keeping old state is the update gate's job. You needed r = 0 for the Clean overwrite challenge.
4. Hidden size n, input size d. Which has the most parameters?
4, 3 and 1 blocks of n·(n + d) + n. In the demo: 347k, 265k and 99k.
5. Something a GRU cannot do that an LSTM can?
With no output gate and no separate cell state, whatever the GRU remembers is in ht, which everything downstream sees. It can hold values (z = 1) and has the gradient highway, and like any RNN it handles any length.
6. An interviewer asks “LSTM or GRU?” Best short answer?
Comparisons (Chung et al. 2014; Greff et al. 2015) find them about equal. Add the trade-off: GRU is smaller and faster, LSTM has the extra output gate and separate memory.

Say it out loud

Write the GRU equations and say what each gate does.
r = σ(Wr·[ht−1, xt] + br), z = σ(Wz·[ht−1, xt] + bz), h̃ = tanh(Wh·[r ⊙ ht−1, xt] + bh), ht = z ⊙ ht−1 + (1 − z) ⊙ h̃. Update gate: keep the old state vs take the candidate. Reset gate: how much old state the candidate sees.
LSTM vs GRU in 30 seconds.
Both add gates and an additive path through time to fix vanishing gradients. The LSTM has a separate cell state and three gates (forget, input, output). The GRU merges the states and uses two gates (update, reset), tying forget and input together and dropping the output gate. The GRU has about 3/4 the parameters and is faster. Accuracy is usually similar, so pick empirically.
Why does a GRU not suffer from vanishing gradients as badly as a vanilla RNN?
The z ⊙ ht−1 term is a direct path from old state to new with no weight matrix or tanh. Along it the per-step factor is z, which the network can hold near 1, so the gradient survives many steps.
